# ADR 0002: пиксельная кириллица в растровых шрифтах диска

## Статус
Принято (A1–A3 из SPEC закрывает тикет T4a; если они не подтвердятся — пересмотр)

## Дата
2026-10-21

## Контекст
- Раскладку текста (advance = a+b+c, кернинг, перенос) порт всегда берёт из растрового FONT диска,
  даже при HD-шрифте `.sdfont` (`platform/include/port_hd_font.h`). Символ без глифа в FONT
  не рисуется и места не занимает (`CRasterFont::GetSize` пропускает `nullptr`).
- Шрифты USA-диска: 96 глифов ASCII + ®. Нет кириллицы, «», —, …, ’, °.
- Пять шрифтов Deface (FONT v2) несут весь игровой текст: `B5BC844E` 13B, `C29C51F1` 14B_O
  (с контуром), `192BB274` Head14B, `B7BBD0B4` 18B, `FE94BD23` 24B. Ещё два не трогаем:
  `9BB52E75` — 12 глифов (цифры, `.:`), `30707C0C` — японские имена в титрах (`&font=` в STRG).
- Атлас — TXTR C4 одной мипы, палитра использует только 0 (фон), 1 (заливка), 2 (контур).
  Глифы 1-битные, без сглаживания, стиль блочный пиксельный.
- Глиф, который уже есть в FONT, порт не заменяет своим stand-in'ом
  (`CRasterFont::PortAddStandIns`: `HasGlyph` → пропуск); атлас порт и сам умеет наращивать
  в высоту (`PortAddAccents`), значит, высота TXTR не зашита.
- Отображаемый текст в верхний регистр не переводится (`toupper` в коде только для FourCC).

## Решение
Дорисовать в каждый из пяти шрифтов Deface 1-битные глифы: `А–Я а–я Ё ё « » — …`.
- Буквы, совпадающие по форме с латиницей этого шрифта, — копии латинских ячеек:
  А В Е К М Н О Р С Т Х, а е о р с у х (и прочие, где совпадение подтверждено превью).
- Я, И — зеркальные R, N; остальные рисуются генератором из прямоугольных штрихов,
  параметризованных метриками латиницы того же шрифта (высота H и x, толщина стема, отступы).
  Контур для `C29C51F1` — дилатация на 1 пиксель индексом 2, как у латиницы.
- Ё/ё — Е/е + две точки (как у `PortFontAccent`).
- Новые ячейки дописываются в атлас снизу полками с зазором 1 px; высота атласа — **степень двойки**
  (порт сам наращивает атласы Deface под свои stand-in'ы в `PortAddAccents` и рассчитан на POT);
  UV старых глифов пересчитываются под новую высоту, латиница не меняется пиксельно.
- UV новых ячеек — по схеме диска: на полпикселя за ячейку с каждой стороны.
- `kern_start` новых глифов = число пар кернинга (как у глифов диска без пар): `KernLookup`
  индексирует таблицу без проверки границ.
- a/b/c и baseline новых глифов — по латинскому аналогу или по H; кернинг для кириллицы не добавляем.

## Рассмотренные альтернативы

### TTF-донор, рендер в 1 бит
- За: быстро, все символы сразу.
- Против: на 13–24 px в 1 бит без сглаживания чужой шрифт выглядит иначе по толщине и
  форме; Deface блочный, похожего TTF с кириллицей под рукой нет.
- Отклонено владельцем в пользу стиля Deface.

### Только HD `.sdfont` с кириллицей
- Против: раскладка всё равно из растрового FONT — без растрового глифа символ не занимает места.
- Отклонено; `.sdfont` — позже (TR2), поверх этого решения.

### Шрифты PAL-диска
- Против: у пользователя нет PAL-образа; в PAL нет кириллицы, только латиница с диакритикой.
- Отклонено.

## Последствия
- Атласы растут до следующей степени двойки (256×128 → 256×256, +16 КБ при 4 бит). Heap — проверка A2 в T4a.
- ° порт уже рисует своим stand-in'ом ('o'); «, », —, … свои stand-in'ы тоже есть, но наши глифы их отключают (`HasGlyph`).
- Нужен генератор и превью на каждый кегль; дизайн глифов утверждает владелец (Чекпоинт 1–2).
- Наш FONT подменяет шрифт для всех языков — латинские ячейки обязаны остаться побайтно прежними
  (проверка в тесте генератора).
